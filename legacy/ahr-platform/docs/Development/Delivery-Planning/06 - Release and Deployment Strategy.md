# AHR Platform — Release & Deployment Strategy

## السؤال الذي تجيب عنه هذه الوثيقة
كيف يُطلَق أي إصدار جديد من المنصة بأمان؟ مبادئ إطلاق، لا آليات نشر تقنية بعينها.

## مبادئ الإطلاق

1. **الإطلاق التدريجي لا الدفعة الواحدة**: أي تغيير جوهري يُطلَق تدريجيًا (نطاق محدود ثم توسّع)، لا لكل المستخدمين دفعة واحدة، حيثما أمكن ذلك دون كسر تجربة موحّدة.
2. **قابلية التراجع الفورية**: كل إصدار يملك مسار تراجع سريع للإصدار السابق دون فقدان بيانات أُدخلت خلاله (اتساقًا مع Archive Model — Phase 4).
3. **بوابة اعتماد إلزامية قبل الإنتاج**: لا إصدار يصل لبيئة الإنتاج دون اجتياز طبقات التحقق في Testing Architecture واعتماد صريح (Delivery Governance).
4. **الإصدار لا يغيّر قواعد معتمدة ضمنيًا**: أي إصدار يمس Business Rules أو Data Integrity Rules يتطلب مراجعة معمارية موثقة قبل الإطلاق، لا كجزء عرضي من إصدار تقني روتيني.

## نافذة الإطلاق والتواصل

أي إطلاق يؤثر على تجربة مستخدمين نشطين (تغيير في Navigation Architecture أو Sitemap) يُصاحَب بإشعار مسبق حيثما أمكن، اتساقًا مع مبدأ الوضوح في UX Principles (Phase 7).

## ما لا تتضمنه هذه الوثيقة

- لا آليات نشر تقنية أو أدوات أتمتة بعينها (CI/CD تُفصَّل تقنيًا في Phase 10).
- لا جدول زمني للإصدارات.
