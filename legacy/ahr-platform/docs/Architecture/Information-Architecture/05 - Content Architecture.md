# AHR Platform — Content Architecture

## السؤال الذي تجيب عنه هذه الوثيقة
ما هي أنواع المحتوى الأساسية التي تتكون منها منظومة AHR معلوماتيًا، وكيف ترتبط ببعضها مفاهيميًا؟

هذه وثيقة **معلوماتية-مفاهيمية فقط**. لا تتضمن جداول قاعدة بيانات أو حقولاً تقنية (ذلك موضوع Database Architecture — Phase 4)، ولا تتضمن روابط أو صفحات فعلية (ذلك موضوع Site Map)، ولا تصميم واجهات (UX/UI لاحقًا).

## أنواع المحتوى الأساسية (Core Content Types)

| النوع | الوصف المفاهيمي |
|---|---|
| **Person** | أي فرد داخل المنظومة — سواء Foundational Personal Brand نفسه أو أي فنان/متدرب/عضو موثّق |
| **Work** | أي وحدة إبداعية موثّقة ومنجزة (أغنية، عمل مسرحي، مسلسل...) |
| **Contribution** | العلاقة الدقيقة التي تربط Person بـ Work أو Project أو Event، وتحدد طبيعة دوره فيه |
| **Project** | نشاط مستمر لا يُصنَّف كعمل فني منجز منفرد (تدريب، تحكيم، مبادرة) |
| **Organization** | أي مؤسسة أو جهة رسمية مرتبطة بالمحتوى |
| **Award** | جائزة أو تكريم أو عضوية رسمية |
| **Event** | فعالية محددة بتاريخ ومكان |
| **Media** | أي ملف بصري أو سمعي مرتبط بأي كيان آخر |
| **Press** | أي تغطية صحفية أو إعلامية خارجية |
| **Category** | تصنيف هرمي (Hierarchical Classification) — بنية تفرّع من عام إلى خاص |
| **Tag** | وسم وصفي غير هرمي (Non-Hierarchical Descriptive Label) — يُستخدم بحرّية دون بنية تفرّع |

### ملاحظة مهمة

داخل نموذج المعلومات الخاص بـ AHR، يمثّل "Person" كيانَ محتوى (Content Entity) يصف فردًا داخل منظومة المعرفة الخاصة بالمنصة.

قد يكون لدى Person حساب على المنصة أو لا يكون.

عندما يحصل Person على وصول للمنصة، فقد يصبح **User**.

يمكن لنفس الـ Person أن يحمل أكثر من دور في نفس الوقت (مثال: فنان، طالب، مدرّب، مؤسس، مسؤول، أو عضو)، تبعًا لعلاقته بخدمات AHR المختلفة.

النموذج التفصيلي للهوية، ونموذج المصادقة، والصلاحيات، وحسابات المستخدمين، كل ذلك خارج نطاق هذه الوثيقة عمدًا، وسيُحدَّد في مراحل معمارية لاحقة.

## علاقة هذه الوثيقة بالأرشيف الحالي

هذه الأنواع مأخوذة من التوثيق المعماري الموجود فعليًا في الأرشيف (AHR Architecture FROZEN وEntities Catalog من الأصول القائمة، المُشار إليها في Audit Report — Phase 0). هذه الوثيقة **تُثبّتها كمرجع معلوماتي رسمي لـ Phase 3**، ولا تعيد تصميمها من الصفر.

## مبدأ العلاقة بين الأنواع

كل أنواع المحتوى ترتبط عبر **Person** و**Contribution** كمحورين مركزيين: لا يوجد Work أو Project أو Event بلا Contribution واحد على الأقل يربطه بـ Person. هذا يضمن أن المحتوى لا يظهر معزولاً عن صاحبه أو المسؤول عنه.

## ما لا تتضمنه هذه الوثيقة

- لا تتضمن حقول البيانات التقنية أو أنواعها (ذلك في Database Architecture).
- لا تتضمن الصفحات أو الروابط الفعلية (ذلك في Site Map).
- لا تتضمن تجربة التصفح أو رحلة المستخدم (ذلك في User Journey).
