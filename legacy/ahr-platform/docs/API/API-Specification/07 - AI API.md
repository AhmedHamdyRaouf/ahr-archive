Base path: `/api/ai`

### Request Suggestion

- **Endpoint Name:** Request Suggestion
- **Purpose:** Generate an AI-assisted suggestion (e.g. category assignment, summary text) for a specific field of a specific entity, for human review.
- **Package:** AI
- **HTTP Method:** POST
- **Route:** `/api/ai/suggest`
- **Authentication Required:** Yes
- **Required Role:** Administrator
- **Request Headers:** `Content-Type: application/json`, session cookie
- **Path Parameters:** None
- **Query Parameters:** None
- **Request Body (Input):** `{ "entityType": "works" | "projects" | ..., "entityId": uuid, "kind": "categorySuggestion" | "summarySuggestion" }`
- **Context:** The abstraction layer sends only this specific entity's own fields (title, existing description, existing category/tag assignments) as context to OpenAI — never a bulk export of other records (AI Data Access Model, Phase 5). No conversation history or prior suggestions are included as context in V1.
- **Permissions:** Administrator only; the request is scoped to entities the Administrator can already see and edit through CMS — no broader data access is granted by virtue of calling this endpoint.
- **Validation Rules:** `entityType`/`entityId` must reference an existing, accessible entity; `kind` must be one of the supported suggestion types.
- **Output:** `200 { "data": { "suggestedContent": ..., "rationale": string, "confidenceLevel": "high" | "medium" | "low", "provider": "openai", "logId": uuid | null } }` — shape matches AI Recommendation Model (Phase 5): target, content, rationale, confidence, all present together, never rationale/confidence omitted. `logId` identifies the `ai_recommendation_log` row this suggestion was recorded as (added 2026-07-21) — `null` only if the log write itself failed, which never blocks or fails the suggestion response.
- **Limitations:** Suggestions are advisory only — this endpoint never writes to the target entity itself (AI Decision Boundaries, Phase 5); one suggestion kind per call (no batch/bulk suggestion requests in V1); English/Arabic suggestion quality is not independently guaranteed identical, since it depends on the underlying OpenAI model's own bilingual capability, not something this platform controls.
- **Error Handling:** `502 PROVIDER_UNAVAILABLE` on OpenAI timeout/failure — the CMS form must remain fully usable regardless (Packages Specification Package 06 §19); `404 NOT_FOUND` for an invalid entity reference; `422 VALIDATION_ERROR` for an unsupported `kind` or a missing `entityId`.
- **HTTP Status Codes:** `200`, `404`, `422`, `502`.
- **Business Rules:** AI Decision Boundaries (Phase 5) — this endpoint may only ever return a suggestion; it has no corresponding "apply" endpoint of its own (accepting a suggestion is expressed as a normal `PATCH`/taxonomy call on the CMS entity itself, using the suggested value as if it were manually entered — see 03 - CMS API).
- **Notes:** `entityId` became a required body field 2026-07-21 (previously accepted but unused) — see the Resolve endpoint below for why.

### Resolve Suggestion Outcome

- **Endpoint Name:** Resolve Suggestion Outcome
- **Purpose:** Record what the Administrator did with a previously-generated suggestion (accepted, edited then applied, or rejected) — added 2026-07-21 alongside `ai_recommendation_log`'s activation (Database Architecture Review Round item E3).
- **Package:** AI
- **HTTP Method:** PATCH
- **Route:** `/api/ai/suggest/{logId}/resolve`
- **Authentication Required:** Yes
- **Required Role:** Administrator
- **Path Parameters:** `logId` — the value returned as `logId` by the Request Suggestion call this is resolving.
- **Request Body (Input):** `{ "outcome": "accepted" | "edited" | "rejected" }`
- **Output:** `200 { "data": { "ok": true }, "error": null }`
- **Error Handling:** `422 VALIDATION_ERROR` for an unrecognized `outcome` value.
- **HTTP Status Codes:** `200`, `422`.
- **Business Rules:** This is not a second "apply" endpoint (AI Decision Boundaries still holds — see the endpoint above) — it only ever updates `ai_recommendation_log.outcome`/`resolved_at`, never the target entity. The client (AISuggestionPanel) calls this fire-and-forget immediately after Accept/Reject; a failure here never blocks or reverses the Administrator's actual action on the form.

## Persistence — Resolved 2026-07-21

**`ai_recommendation_log` now exists** (`packages/database/migrations/20260721100000_ai_recommendation_log.sql`), activated per the Database Architecture Review Round item E3, approved by the data owner 2026-07-21 (see `docs/Program-Status/Decision-Log.md`). Every suggestion generated by `POST /api/ai/suggest` is recorded as `pending`, then updated to `accepted`/`edited`/`rejected` by the Resolve endpoint above.

**Still not built:** a history-listing endpoint (`GET /api/ai/suggestions` / `GET /api/ai/suggestions/{id}`) to actually read this log back through the API — the table exists and is being written to, but nothing yet exposes it for an Administrator to browse past suggestions. This is a smaller remaining task than the original schema gap, tracked as new Development work.
