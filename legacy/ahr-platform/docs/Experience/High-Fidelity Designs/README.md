# AHR Platform v1 — High-Fidelity Designs

**Status:** 🔴 Cannot reach visual completion until Brand Identity (B10) resolves — composition-level specification is complete

## Scope Note
A true "high-fidelity design" applies literal color, type, and imagery values to a layout. Since those values are Open Decision B10 (see `Design System/README.md`, `Brand Identity/README.md`), no pixel-accurate mockup can be produced without either inventing an unapproved brand (not permitted) or waiting for B10. What this folder delivers instead is the **composition specification** — everything about a screen except the literal visual values — so that the moment B10 resolves, applying it is a styling pass, not a redesign.

## What "Composition-Complete" Means Here
For every screen documented in `Wireframes/`, `Website Designs/`, and `Dashboard Designs/`, the following are already fully specified and require no further design work once B10 resolves:
- Region layout and hierarchy (already in Wireframes/ region maps)
- Which component variant appears where (Components Library/)
- Which color *role* (not value) applies to each element (Design System/ §2)
- Which typography *role* applies to each text element (Design System/ §1)
- Spacing/grid rules per breakpoint (Responsive Designs/)

## What Remains — Explicitly a B10 Dependency, Not a Design Gap
Applying the resolved literal token values (Design Tokens/) to produce an actual rendered mockup. This is recorded as the top item in `Backlog.md` and the top risk in `Design Status Report.md`.
