# AHR Platform — Information Presentation

## السؤال الذي تجيب عنه هذه الوثيقة
كيف يُعرَض المحتوى بصريًا من حيث التسلسل والتجميع والتأكيد؟ هذه مبادئ عرض مفاهيمية — لا تصميم فعلي لصفحة بعينها.

## مبادئ العرض

1. **التسلسل الهرمي للأهمية**: أهم معلومة عن أي كيان (اسم Work، دور Person الأساسي) تظهر أولاً دائمًا، قبل التفاصيل الثانوية — بصرف النظر عن نوع الكيان.
2. **التجميع حسب العلاقة لا الترتيب الزمني فقط**: المعلومات المرتبطة منطقيًا (كل Contributions لعمل واحد) تُعرَض مجمّعة، لا مبعثرة حسب تاريخ الإدخال.
3. **الإفصاح التدريجي (Progressive Disclosure)**: التفاصيل الكثيفة (Metadata كاملة، سجل تاريخي) تُتاح عند الطلب، لا تُعرض كلها دفعة واحدة بشكل يُرهق القراءة.
4. **الإشارة البصرية لحالة التوثيق**: أي تفاوت في Verification Status (Data Lifecycle — Phase 4) يظهر بإشارة واضحة ومفهومة للمستخدم العادي، لا مصطلح تقني.
5. **الاتساق البصري بين اللغتين**: نفس تسلسل الأهمية ونفس مبدأ التجميع في العربية والإنجليزية، مع مراعاة اتجاه القراءة (RTL/LTR) دون كسر التسلسل المنطقي.

## علاقة العرض بالتصنيف

عرض Category وTag (Content Taxonomy — Phase 3) يعكس فرقهما المفاهيمي: التصنيف الهرمي يُقدَّم كمسار تصفح (Breadcrumb-like)، بينما الوسوم تُقدَّم كعناصر أفقية قابلة للاستكشاف الحر.

## ما لا تتضمنه هذه الوثيقة

- لا تعيد تعريف أنواع المحتوى نفسها (Content Architecture — Phase 3/4).
- لا تتضمن تخطيط شبكي أو مقاسات فعلية (Design System Foundations).
