# AHR Platform — Interaction Patterns

## السؤال الذي تجيب عنه هذه الوثيقة
كيف يتلقى المستخدم استجابة لأفعاله عبر المنصة؟ أنماط تفاعل مفاهيمية عامة، لا تصميم عناصر واجهة فعلي.

## الأنماط الأساسية

1. **استجابة فورية لكل فعل**: أي إجراء يتخذه المستخدم (إرسال طلب تعاون، تقديم بلاغ) يقابله تأكيد فوري بأن الفعل استُقبل، حتى لو كانت المعالجة الفعلية تستغرق وقتًا.
2. **وضوح حالة الانتظار**: أي عملية تتطلب مراجعة بشرية (Human-in-the-Loop — Phase 5) تُعرَض بوضوح كـ"قيد المراجعة"، لا كخطأ أو غياب استجابة.
3. **رسائل الخطأ التوجيهية**: أي خطأ يُقدَّم مع توضيح للسبب وخطوة تالية مقترحة، لا رمز خطأ مجرد.
4. **التأكيد قبل الأثر الجوهري**: أي فعل يغيّر حالة كيان بشكل ملموس (طلب أرشفة، تقديم بلاغ) يمر بخطوة تأكيد صريحة قبل التنفيذ.
5. **التراجع حيثما أمكن**: الأفعال القابلة للتراجع (وفق Data Lifecycle — Phase 4: لا حذف نهائي) تتيح للمستخدم خيار التراجع الفوري بعد التنفيذ مباشرة.

## نمط عرض توصيات الذكاء الاصطناعي

أي توصية ذكاء اصطناعي (AI Recommendation Model — Phase 5) تُعرَض بنمط تفاعلي موحّد: محتوى مقترح + مستوى ثقة + خيار قبول/تعديل/رفض صريح في نفس السياق، لا كنص عابر بلا إجراء واضح.

### تفاوت أدوات التفاعل حسب الدور

أدوات التحكم المتاحة على توصية الذكاء الاصطناعي تختلف حسب دور المستخدم الحالي (Users — Phase 1). مثال: المسؤول يملك أدوات قبول/تعديل/رفض كاملة، بينما الزائر أو الطالب قد يرى التوصية كمعلومة توضيحية فقط دون أدوات تنفيذ. لا تُعرَض أدوات تفاعل تتجاوز صلاحية الدور الحالي (اتساقًا مع Ownership Rules — Phase 6).

### تفاوت أدوات التفاعل حسب الدور

أدوات التحكم المتاحة لتوصية الذكاء الاصطناعي تختلف حسب دور المستخدم الحالي (Users — Phase 1): المسؤول قد يملك خيارات قبول/تعديل/رفض كاملة، بينما مستخدم بدور أضيق قد يقتصر تفاعله على الإطلاع أو الإبلاغ فقط. لا تُعرض كل أدوات التحكم لكل الأدوار بشكل موحّد بصرف النظر عن صلاحياتها (اتساقًا مع Ownership Rules وBusiness Rules — Phase 6).

## ما لا تتضمنه هذه الوثيقة

- لا تصميم عناصر واجهة فعلية (أزرار، حقول) — Design System Foundations.
- لا تتضمن منطق العمل خلف كل فعل (Business Logic — Phase 6).
