# AHR Platform — Integration Architecture

## السؤال الذي تجيب عنه هذه الوثيقة
كيف تتكامل الخدمات المنطقية مع بعضها، ومع الأنظمة الخارجية (مصادر خارجية موثّقة، مراجع Press)؟

## مبادئ التكامل الداخلي

1. **العقد قبل التنفيذ**: أي خدمتين تتواصلان عبر عقد منطقي محدد مسبقًا (ما تستقبله، ما تُرجعه)، لا اعتماد ضمني على تفاصيل تنفيذ الطرف الآخر.
2. **التزام العقد لا كسره**: أي تغيير في خدمة لا يجوز أن يكسر العقد المتفق عليه مع خدمات أخرى دون تحديث العقد نفسه أولاً.
3. **لا اتصال دائري غير ضروري**: خدمة أ تستدعي خدمة ب، لا يجوز أن تستدعي ب أ مرة أخرى ضمن نفس العملية دون غرض واضح (لتفادي التعقيد غير الضروري).
4. **الفشل المعزول**: تعطّل خدمة واحدة (مثال: خدمة الإشعارات) لا يوقف عمل خدمة أخرى غير معتمدة عليها مباشرة (خدمة المحتوى تستمر بالعمل حتى لو تعطلت الإشعارات).

## التكامل مع مصادر خارجية

مصادر خارجية (تغطية صحفية — Press، مراجع خارجية — External Reference وفق Identifier Strategy، Phase 4) تُدمَج كإشارات موثّقة، لا كمصدر حقيقة بديل عن AHR Core. أي بيانات من مصدر خارجي تمر عبر خدمة المحتوى للتحقق قبل الربط.

## التكامل مع الذكاء الاصطناعي

خدمة تشغيل الذكاء الاصطناعي (Service Architecture) تتكامل مع خدمة المحتوى وخدمة التحقق عبر طلبات قراءة محدودة النطاق (AI Data Access Model — Phase 5)، ولا تُمنح وصولاً كتابيًا مباشرًا لأي خدمة أخرى — أي أثر كتابي يمر عبر خدمة الإشراف/التحقق بعد قرار بشري.

## ما لا تتضمنه هذه الوثيقة

- لا تحدد بروتوكول أو تنسيق تبادل البيانات الفعلي (تُحسم في Phase 9).
- لا تحدد أدوات أو منصات تكامل بعينها.
