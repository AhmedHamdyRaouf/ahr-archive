# AHR Platform — AI Runtime Architecture

## السؤال الذي تجيب عنه هذه الوثيقة
كيف يعمل الذكاء الاصطناعي تقنيًا في وقت التشغيل، ضمن الحدود المعتمدة في Phase 5، دون اختيار نموذج أو مزوّد بعينه؟

## مبدأ العزل التشغيلي

تشغيل الذكاء الاصطناعي يتم ضمن حدود معزولة (Isolated Execution Boundary) لا تملك وصولاً كتابيًا مباشرًا لأي نظام بيانات مركزي. أي مخرج يمر عبر خدمة تشغيل الذكاء الاصطناعي (Service Architecture) كطلب مقترح، لا كتنفيذ مباشر.

## دورة الطلب التقنية

```
① طلب/سياق يصل لخدمة تشغيل الذكاء الاصطناعي
        ↓
② الخدمة تجلب البيانات المسموح بها فقط (AI Data Access Model — Phase 5)
        ↓
③ توليد مخرج مرفق بأساس منطقي ومستوى ثقة (AI Recommendation Model، AI Confidence Model)
        ↓
④ تسجيل الطلب والمخرج في سجل تتبع دائم (Observability — قابلية تدقيق كل قرار)
        ↓
⑤ تسليم المخرج لقائمة مراجعة بشرية (Human-in-the-Loop Architecture) قبل أي أثر فعلي
```

## مبدأ عدم الحالة الدائمة غير المصرَّح بها

خدمة تشغيل الذكاء الاصطناعي لا تحتفظ بحالة دائمة مؤثرة على النظام (لا تُعدِّل كيانًا مباشرة). أي "ذاكرة" يحتاجها للسياق تبقى محصورة داخل حدود الطلب، أو تُخزَّن كبيانات مساعدة منفصلة تمامًا عن نظام البيانات المركزي.

## استثناء طبقة العرض

العمليات المعتمدة كاستثناء في AI Decision Boundaries (ترتيب نتائج، تخصيص عرضي) تُنفَّذ داخل خدمة البحث أو التجربة مباشرة، لا داخل خدمة تشغيل الذكاء الاصطناعي نفسها، لإبقاء الفصل واضحًا بين "اقتراح يحتاج مراجعة" و"تحسين عرض لا يغيّر حالة".

## ما لا تتضمنه هذه الوثيقة

- لا تحدد نموذج الذكاء الاصطناعي أو مزوّده (Future Technical Evolution / Phase 9).
- لا تحدد البنية التحتية لتشغيل النموذج (استضافة، عتاد).
